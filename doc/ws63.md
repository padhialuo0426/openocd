# WS63 分支功能参考

本分支在 OpenOCD 上游源码中增加 WS63 的 SWD 调试支持，面向 BearPi-Pico H3863。
这是持续维护的开发适配，适用范围和使用边界如下。
CPU 控制、Flash 擦写和 LiteOS 线程服务均在 OpenOCD 内实现，运行时不依赖 `ws63_dbg`。
[构建与连接方法](ws63-setup.md)给出本分支的使用步骤。

## 1. 适用条件

- 主控为 WS63，探针通过 SWD 连接。固件已把 GPIO13/GPIO14 配置为调试引脚。
- Flash 驱动要求启动固件已初始化 SFC，将 GD25Q32 的 4 MiB 空间映射到 `0x200000`。
- LiteOS 适配限定于 BearPi SDK v1.0.102 的 RV32F 布局：`LosTaskCB` 为 96 字节，
  `TaskContext` 为 272 字节。必须提供与运行固件匹配的 ELF。
- 开发环境为 Linux。CMSIS-DAP v2 bulk 可协商 512 字节包；实际传输能力取决于探针。
  上游保留 CMSIS-DAP v1 HID 驱动，本分支未重新验证 v1 硬件及其他宿主机系统。

## 2. 当前实现

| 能力 | 接口与范围 |
|---|---|
| AP0 CPU 调试 | RISC-V Debug Module 经 AP0 访问；暂停、继续、硬件单步、GPR、FPR 和芯片支持的 CSR |
| AP1 总线访问 | `WS63.ap1` 提供 8/16/32 位访问；支持 ROM、Flash、RAM 和外设地址。AP0/AP1 可交替使用 |
| GDB 源码调试 | `break`、`hbreak`、`step`、`next`、`finish`、条件断点、命中计数和目标函数调用；符号和源码由 ELF 提供 |
| 内存与缓存 | CPU 视图中的 RAM 访问经 program buffer；ROM、Flash 和 MMIO 访问经 AP1。RAM 写入后执行缓存维护 |
| 断点 | RAM 软件断点、ROM/Flash 硬件断点；可选择启用 Flash 软件断点，支持移除、跨断点单步和重插 |
| 数据观察点 | 读、写、读写；多个观察范围与非对齐范围；拆分占用硬件槽位，识别实际标量访存与边界误触发 |
| 复位 | 已连接时通过 `ndmreset` 暂停在 `0x100000`；恢复连接后重新安装硬件断点和观察点 |
| NOR Flash | GD25Q32 识别、4 KiB 扇区擦除、编程、SPI 读回校验、保护位恢复；支持 OpenOCD Flash 命令及 GDB `load` |
| LiteOS 线程 | `info threads`、`thread`、`thread apply all bt`；展示任务名、状态、优先级及已保存的上下文 |
| ELF 展开信息 | `contrib/ws63/prepare_elf.py` 为可识别的 WS63 栈操作补充 CFI，并生成 LiteOS 符号配置；不改变可加载字节 |
| 内存导出 | OpenOCD `dump_image`、`ws63_ap1_dump` 和 GDB `dump binary memory` |

## 3. 使用边界

### 3.1 调试、复位与缓存

AP1 读取 RAM 不会自动读取 CPU 缓存中的脏数据。需要一致的 RAM 转储时，先暂停 CPU，
执行 `ws63_ap1_sync_dcache`，再导出。直接通过 AP1 改写代码后，执行 `ws63_sync_code`。
外设寄存器可能具有读清零或写触发行为，按芯片寄存器定义访问。

`reset halt` 是已开启调试接口后的复位调试，不等同于上电第一条指令拦截。
启动过程中若固件执行全芯片复位，SWD 可能暂时断开；后端在接口恢复后重新检查目标。
上电时调试引脚未复用到 SWD 的板卡仍需由已有固件开启接口。

硬件断点与观察点共用触发器，范围拆分可能消耗多个槽位。观察点命中解码覆盖自然对齐的
RV32 标量访问、压缩访存和 WS63 短字节/半字指令。遇到未知、多寄存器或非对齐访存时保留暂停，
不自动跳过。GDB 的条件判断发生在主机端，不能消除每次命中的暂停开销。

### 3.2 Flash

默认将 Flash 软件断点请求转换为硬件断点。显式设置 `WS63_FLASH_SWBP=1` 后才允许改写 Flash。
软件断点按扇区保存和改写，具有擦写开销；断开前先删除断点。
先用硬件断点进入已完成启动校验的应用，再插入 Flash 软件断点；提前改写签名镜像会干扰启动校验。
需要改写已设置软件断点的代码时，先删除断点，避免后续恢复原指令覆盖新代码。

擦除及编程前在 `WS63_FLASH_BACKUP_DIR` 保存原始字节，文件名包含 XIP 起始地址。
备份失败则不执行该次操作。备份是原始数据文件，不包含 Python 工具的事务清单、校验清单或自动恢复协议。
编程不替读者维护签名、分区表或固件包格式；普通 `load` 只按 ELF 的加载地址写入，
擦除涉及整个扇区，扇区内未被镜像覆盖的数据必须另行保存。

普通 Flash 擦写完成后，必须复位再运行；软件断点内部的整扇区替换不要求复位。
操作失败会阻止当前会话继续或复位。恢复并核对所有受影响的数据后，重新启动 OpenOCD 会话。
该阻止状态仅存在于进程内，不能代替断电后的人工恢复检查。

### 3.3 LiteOS

非当前任务是只读上下文视图，只展示调度器可靠保存的寄存器；其余寄存器显示为 `<unavailable>`。
在该视图中拒绝寄存器写入和单步，切回当前任务后执行这些操作。
`thread` 不会切换芯片上的实际运行任务，也不提供单任务运行或调度锁定。

ELF 准备工具检查上述结构体布局，但 OpenOCD 不会自动证明 ELF 与 Flash 内容一致。
缺少符号/CFI 的 ROM、异常入口及无法识别的栈操作仍可能中断回溯。
